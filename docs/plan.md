# 開発計画

## 1. 全体像

サイトは大きく3つの部品でできている。

- **シーン**：一枚絵と、その上に重ねる動く部分。複数のシーンを切り替えられる
- **音**：音楽（YouTube／同梱曲／手元の曲）と、店の環境音
- **イベントの流れ**：音と絵をつなぐ。「シェイクの音が鳴った」というイベントで、シェイカーのコマが動き出す

```
[注文スケジューラ] --event--> [イベントバス] --> [環境音エンジン]（音を鳴らす）
                                          \-> [シーン描画]（コマ・部品を動かす）
                                          \-> [状態表示]（絵の下の1行）
```

## 2. 絵：一枚絵＋動く部分

ベースは、オーナーが用意する静止画（16:9、斜めから見た構図、線画＋網点＋少数色のタッチ）。
その上に動く部分をレイヤーとして重ねる。

### 動きの3分類

| 種類 | 例 | 作り方 |
|---|---|---|
| 移動（`sprite-move`） | 窓の外を車や人が通る、雨 | 背景透過の部品を、切り抜き範囲（窓の形など）の中で経路に沿って動かす。等速の移動なので、コードで動かしても自然に見える |
| 変形（`frames`） | ページをめくる、シェイカーを振る、注ぐ | コマ打ちアニメ。動く範囲だけを切り出した数コマを、8〜12fps で差し替える。影や机の木目もコマに含めるので、影がずれない |
| 光・空気（`overlay`） | ランプの揺らぎ、ろうそく、湯気、車のライトが室内をなでる | 重ね合わせのレイヤーを、透明度・合成モード・ゆっくりした変位で変化させる |

ベース画像そのものは一切書き換えない。変形は「パッチ（四角い範囲）の差し替え」で行う。

### シーンの候補（オーナーの参考画像3枚より）

| シーン | 色 | 動きの候補 |
|---|---|---|
| バーのカウンター | オリーブ | シェイカー、注ぐ、ランプの揺らぎ、グラスが置かれる |
| 窓際のカフェ席 | マスタード | 車、通行人、ページめくり、湯気 |
| レコードのある部屋 | セージ＋テラコッタ | レコードの回転、トーンアーム、観葉植物の揺れ、湯気 |

最初の検証には、窓際のカフェ席を使う（3種類の動きがそろうため）。

## 3. シーンの定義（JSON の案）

```jsonc
{
  "id": "cafe-window",
  "title": "窓際の席",
  "accent": "#D6AA3F",
  "size": [2560, 1440],                    // 論理解像度。描画はこれを基準に拡縮する
  "base": "scenes/cafe-window/base.webp",
  "soundPack": "cafe",
  "clips": {
    "window": [[120, 60], [1700, 60], [1700, 1150], [120, 1200]]  // 切り抜き範囲（多角形）
  },
  "layers": [
    {
      "id": "car", "type": "sprite-move",
      "image": "scenes/cafe-window/car.webp",
      "clip": "window",
      "path": [[-400, 820], [2000, 780]], "duration": [5, 8],
      "trigger": { "every": [60, 240] },
      "emits": "car-pass"                   // 音側に「車が通った」を伝える
    },
    {
      "id": "page", "type": "frames",
      "rect": [1180, 1430, 520, 320],        // パッチの位置とサイズ
      "frames": ["page/01.webp", "page/02.webp", "page/03.webp", "page/04.webp"],
      "fps": 10,
      "trigger": { "every": [180, 600] },
      "emits": "page-turn"
    },
    {
      "id": "steam", "type": "overlay",
      "image": "scenes/cafe-window/steam.webp",
      "blend": "screen", "effect": "drift", "loop": true
    },
    {
      "id": "shaker", "type": "frames",
      "rect": [0, 0, 0, 0], "frames": [], "fps": 12,
      "trigger": { "on": "order.shake" }       // 音側のイベントで動き出す例
    }
  ]
}
```

- `trigger` は「ランダムな間隔（`every`）」か「イベント（`on`）」のどちらか
- `emits` は、絵が自発的に動いたときに音を鳴らすためのイベント名
- 座標はすべてベース画像のピクセル座標

## 4. 素材の受け取りと変換（`tools/`）

オーナーの作業を減らすため、変換はスクリプトで行う。

| 素材 | オーナーが置くもの | スクリプトの処理 |
|---|---|---|
| ベース画像 | 16:9 の PNG（2560×1440 以上） | 2560×1440 にそろえ、WebP を書き出す |
| 動かす部品 | 背景透過の PNG | WebP（透過）を書き出す |
| 変形のコマ | ベースと同じサイズの全体画像をコマ数ぶん | ベースとの差分を検出し、全コマの差分を包む範囲を `rect` として切り出す。差分の外側の小さなずれは閾値で無視する |
| 切り抜き範囲 | 不要 | 開発用ページで描いて指定する |
| 動く物を消した背景 | 物が画面から消える動きのときだけ | WebP を書き出す |

原本は `assets/source/<scene>/` に置き、変換結果は `public/scenes/<scene>/` に出力する。

## 5. 音

### 音楽

- 曲のリストは1つで、YouTube（動画・プレイリスト）、同梱曲、手元の曲を混在できる
- リストはユーザーが編集できる：オン・オフ、並べ替え、追加、削除、JSON の書き出し・読み込み、初期状態に戻す（UI はモックにある）
- リストは localStorage に、手元の曲のファイル本体は IndexedDB に保存する。初期リストはリポジトリ内の JSON から読む
- 同梱曲と手元の曲は Web Audio を通すので、音質の加工（「店のスピーカー越し」の EQ など）ができる
- YouTube は、仕組み上、音質の加工ができない。IFrame API の `setVolume` で音量だけ制御する
- カクテルを作る間は音楽を少し下げる（ダッキング）。YouTube も `setVolume` を段階的に変えて行う
- フォールバック：YouTube の API が読み込めない、オフライン、埋め込み禁止などのエラーが続く、のいずれかの場合は、同梱曲に自動で切り替え、その旨を表示する。復帰したら、次の曲から YouTube に戻す

### 環境音

- サウンドパック（JSON＋音声ファイル）で定義する。シーンごとにパックを割り当てる
- 中身はループ（ざわめき、ルームトーン、雨）と単発の音（グラス、氷など）、カクテルの手順（シェイク系／ステア系／ビルド系）
- 単発の音は、同じ場面に複数の素材を用意し、毎回ランダムに選んで、ピッチ・音量・左右の定位を少しずつ揺らす
- 注文の間隔はランダム（平均はユーザーが設定）。手順の各段階でイベントを出し、状態表示とシーンに伝える

## 6. UI（`docs/mock/index.html` が基準）

- 縦に「タイトル → 絵 → 状態の1行 → プレイヤー」と並べる。周囲に紙の余白を残す
- 設定パネル：「曲のリスト」「音のバランス」のタブ。シーンの切り替えもここか、絵の近くに小さく置く（未決、5章の検討事項を参照）
- モックの絵はコードで描いた仮のもの。実装ではシーン画像に置き換える
- モバイル：絵は中央を 4:3 で切り出し、音量は設定パネル側に寄せる

## 7. 進める順番

各段階の「完了の目安」を満たしてから次へ進む。

1. **土台**：Vite＋TS の雛形、GitHub Actions による Pages デプロイ、モックの UI を移植。ベース画像1枚が余白付きで表示される
   - 完了の目安：Pages の URL で、画像入りのレイアウトが表示される
2. **エンジンの骨組み**：シーン JSON の読み込み、Canvas 描画（拡縮、高 DPI、12fps 上限、非表示時の停止）、イベントバス、音楽プレイヤー（YouTube と同梱曲、フォールバック）、曲のリスト編集と保存
   - 完了の目安：仮の素材で、曲の再生・切り替え・フォールバックが動く
3. **1シーンで検証（窓際のカフェ席）**：移動・変形・光の3種類を1つずつ実装する。素材変換スクリプトも作る
   - 完了の目安：オーナーの素材で3種類の動きが自然に見える。1つの動きに必要な素材作りの手間を把握できる
4. **開発用ページ（`dev.html`）**：ベース画像の上で範囲や多角形をドラッグして指定、コマの試し再生、経路の確認、シーン JSON の書き出し
5. **環境音と連動**：サウンドパック、注文スケジューラ、手順のイベント、状態表示、ダッキング。バーのシーンでシェイカーと音を連動させる
6. **シーンを増やして仕上げ**：シーンの切り替え（クロスフェード）、差し色の切り替え、パフォーマンス、アクセシビリティ、クレジットページ

## 8. リスクと検討事項

- **AI で作ったコマの一貫性**：コマ間で絵がぶれると、ちらつく。対策は、差し替え範囲を小さく保つこと、差分の閾値で吸収すること、必要に応じた手直し。段階3で手間を見極める
- **YouTube の埋め込み規約（要確認）**：YouTube API の規約には、プレイヤーの最小サイズや「隠したり覆ったりしない」といった要件がある。音だけ流してプレイヤーを見せない作りは、規約に触れる可能性がある。実装前に最新の規約を確認し、必要なら設定パネルや絵の横に小さくプレイヤーを表示する
- **シーン切り替えの置き場所**：操作を最小限にする方針とのバランスを、段階6までに決める
- **素材のサイズ**：ベース画像は WebP で1枚 500KB 前後を目安にする。コマはパッチだけなので小さく済む見込み
- **ライセンス**：同梱する曲と効果音の出どころとライセンスを、一覧（`docs/credits.md` など）で管理する
